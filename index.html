RP2040/RP2350 PIO Simulator

About this tool

A web-based emulator for the RP2040 and RP2350 Programmable I/O (PIO). Test and debug your PIO assembly code directly in the browser with real-time visualization of registers, FIFOs, GPIOs, and timing.

Fully client-side. Up to four state machines run together on shared instruction memory, GPIOs and IRQ flags: put several .program blocks in the source and they go to SM0, SM1, ... (see "Several state machines" under Simulator pragmas). The assembler follows pioasm (expressions, .define, side-set, delays, .word, RP2350 extensions) and the emulator follows the PIO chapters of the RP2040 and RP2350 datasheets. Settings start at the hardware reset values, so set them the way your C setup code would, or with .in / .out / .set / .fifo / .mov_status in the source.

Unsupported Features
  • Other PIO blocks: irq prev / irq next flags exist but nothing else drives them
  • OUT_STICKY / INLINE_OUT_EN, GPIOs above 31 (GPIOBASE), system-level interrupts and DMA
  • Loading at a non-zero offset (.origin is accepted; the program is loaded at address 0)
Simulator pragmas (#pragma pio_sim)

Pin waveforms, IRQ events, FIFO data (DMA), settings and state machines, set from the source.

Comment lines starting with ; #pragma pio_sim set up the simulation from the source. pioasm ignores them, so they can stay in your real code and are saved with it. Clocks are system clocks counted from reset (the same as state machine cycles at clock div 1). Numbers may be .define names.

Pin waveform: drive an input pin.

; #pragma pio_sim pin 5 hi 3 low 7                 ; high 3 clocks, low 7, repeats forever
; #pragma pio_sim pin 4 low 9 hi 1 count 5         ; repeats 5 times, then stays high
; #pragma pio_sim pin 3 hi delay 12 low 2 hi 2     ; holds high for 12 clocks first

pin <n> [<hi|low> delay <clocks>] <hi|low> <clocks> ... [count <n>]. After count periods the pin holds its last level.

IRQ event: raise or clear an IRQ flag, as another state machine's irq set / irq clear would.

; #pragma pio_sim irq set 5 delay 4 repeat 12      ; raised at clock 4, 16, 28, ...
; #pragma pio_sim irq clear 5 delay 8 repeat 12    ; cleared at clock 8, 20, 32, ...
; #pragma pio_sim irq set 0 delay 20               ; raised once, at clock 20

irq set|clear <n> [delay <clocks>] [repeat <clocks>] [count <n>]. The instruction executed on that clock already sees the new value; a real partner's irq on cycle N is seen at N+1, so use delay N+1. The program can still set and clear the flag itself.

Pin read marks: show in the timing chart the clock whose pin level an instruction read.

    jmp pin, gate
; #pragma pio_sim tag_pin_sample A      ; marks the jmp pin above, in lane A (top) .. E (bottom)

tag_pin_sample <A-E> after a jmp pin or wait ... pin / gpio / jmppin: a dot in the state machine's colour on the pin's row (latest bold, older faded, small while a wait holds). "Mark all pin reads" above the chart marks every read.

FIFO data (DMA): the system's side of the FIFOs, as a DMA channel would do it (the Put / Get buttons by hand).

; #pragma pio_sim dma put 7 1 1 3 3                ; these words, then nothing
; #pragma pio_sim dma put 0xF0F000FF 0x80017FFE loop ; these words over and over
; #pragma pio_sim dma put "Hi!\n"                  ; one word per character
; #pragma pio_sim dma get                          ; read every word pushed

dma [sm <n>] put <word|"text"> ... [loop]: the TX FIFO is topped up before every step; several lines add up, loop starts over at the end. Text escapes: \n \r \t \0 \\ \" \xNN (; or // ends the pragma: write \x3B, \x2F). dma [sm <n>] get: the RX FIFO is emptied after every step; the words read are listed in place of the Get button. Autopull / autopush are the state machine's end of the FIFOs, not this. Scope as for config.

Settings: load the Pin Configuration and Shift & FIFO Control settings on Assemble.

; #pragma pio_sim config out_base 0 out_count 2 set_base 0 sideset_base 4
; #pragma pio_sim config in_base 0 jmp_pin 5 autopull on pull_thresh 8

config <name> <value> ... with names out_base, out_count, set_base, set_count, sideset_base, in_base, in_count, jmp_pin, in_shift / out_shift (left, right), autopush / autopull (on, off), push_thresh, pull_thresh, status_sel (tx, rx, irq), status_n, fifo (txrx, tx, rx, txput, txget, putget), clkdiv (1-65535, e.g. 2.5). ; #pragma pio_sim chip rp2040 (or rp2350) selects the chip whose timing to follow. ; #pragma pio_sim input_sync_bypass 0 2-5 sets INPUT_SYNC_BYPASS (which GPIOs skip the input synchroniser, for the whole block): GPIO numbers and ranges, one mask such as 0x3D, all or none. Settings the source does not name keep whatever the controls show. Before the first .program a config line applies to every state machine; inside a program, to the state machines running it; config sm <n> ... to that one only.

Several state machines: each .program is placed in the shared 32-word instruction memory (at its .origin, or the first free addresses) and runs on SM0, SM1, ... in source order. To choose:

; #pragma pio_sim sm 0 program uart_tx         ; SM0 runs uart_tx
; #pragma pio_sim sm 1 program uart_tx         ; so does SM1 ...
; #pragma pio_sim config sm 1 out_base 4       ; ... on other pins
; #pragma pio_sim sm 2 off

With any sm line, state machines not named stay off. The summary under "State" shows every state machine; the tabs choose whose registers, FIFOs and settings are shown. IRQ flags written by one state machine are seen by all on the next cycle, and when two write the same pin on the same cycle the higher-numbered one wins, as on the chip.
